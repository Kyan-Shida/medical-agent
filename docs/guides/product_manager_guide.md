### 2. 关键指标说明

#### LLM 调用成功率

**定义**：LLM API 调用成功的比例

**计算公式**：
```
成功率 = (成功调用次数 / 总调用次数) × 100%
```

**查看方式**：
```bash
python scripts/view_metrics.py
```

**输出示例**：
```
🤖 LLM 调用指标
--------------------------------------------------------------------------------
总调用次数：150
成功次数：149
失败次数：1
✅ 成功率：99.3%
📝 总 Token 数：15000
⏱️ 平均响应时间：1.85 秒
```

**你的参与方式**：
1. **每日查看** - 早上查看前一天的成功率
2. **异常处理** - 如果低于 95%，需要关注
3. **趋势分析** - 每周分析成功率趋势

**改进行动**：
- 成功率下降 → 检查 API 服务商状态
- 响应时间变长 → 考虑切换模型或优化提示
- Token 消耗过高 → 优化提示词长度

#### RAG 检索命中率

**定义**：RAG 检索返回相关文档的比例

**计算公式**：
```
命中率 = (成功检索次数 / 总检索次数) × 100%
```

**查看方式**：
```bash
python scripts/view_metrics.py
```

**输出示例**：
```
📚 RAG 检索指标
--------------------------------------------------------------------------------
总检索次数：80
成功次数：78
✅ 命中率：97.5%
📄 平均结果数：3.2 个
⏱️ 平均响应时间：0.95 秒
```

**你的参与方式**：
1. **知识库质量评估** - 命中率低说明知识库不足
2. **用户问题分类** - 查看哪些问题是知识库没有的
3. **内容运营** - 补充缺失的知识点

**改进行动**：
- 命中率下降 → 补充知识库文档
- 结果数太少 → 调整检索参数（top_k）
- 响应时间慢 → 优化向量索引

#### 意图识别准确率

**定义**：意图识别高置信度（>0.8）的比例

**计算公式**：
```
高置信度比例 = (置信度>0.8 的次数 / 总识别次数) × 100%
```

**查看方式**：
```bash
python scripts/view_metrics.py
```

**输出示例**：
```
🎯 意图识别指标
--------------------------------------------------------------------------------
总识别次数：200
平均置信度：0.92
高置信度比例：95.0%

意图分布：
  - medical: 120 次 (60.0%)
  - chat: 50 次 (25.0%)
  - health_plan: 20 次 (10.0%)
  - unanswerable: 10 次 (5.0%)
```

**你的参与方式**：
1. **意图分布分析** - 了解用户主要问什么
2. **badcase 分析** - 查看识别错误的案例
3. **规则优化** - 根据业务调整意图定义

**改进行动**：
- 医疗问题占比高 → 加强医疗知识库
- 闲聊占比高 → 优化闲聊体验
- 无法回答占比高 → 补充知识库或调整话术

#### 平均响应时间

**定义**：从用户提问到 AI 回答的平均耗时

**计算公式**：
```
平均响应时间 = 所有请求响应时间之和 / 总请求数
```

**查看方式**：
```bash
python scripts/view_metrics.py
```

**性能分级**：
- 🟢 优秀：< 3 秒
- 🟡 良好：3-5 秒
- 🔴 需改进：> 5 秒

**你的参与方式**：
1. **用户体验监控** - 响应时间直接影响体验
2. **性能优化决策** - 是否需要升级硬件或优化代码
3. **SLA 制定** - 制定服务等级协议

**改进行动**：
- 响应慢 → 优化代码或升级服务器
- LLM 耗时高 → 使用更快的模型
- RAG 耗时高 → 优化向量检索

#### 测试覆盖率

**定义**：测试代码覆盖的百分比

**查看方式**：
```bash
# 运行测试并生成覆盖率报告
pytest --cov=core --cov=utils --cov-report=html

# 查看 HTML 报告
open htmlcov/index.html
```

**你的参与方式**：
1. **质量把控** - 确保覆盖率 > 80%
2. **测试评审** - 参与测试用例评审
3. **上线决策** - 覆盖率不达标不批准上线

**质量标准**：
- 🟢 优秀：> 90%
- 🟡 良好：80-90%
- 🔴 需改进：< 80%

## 🔧 实际操作示例

### 示例 1：发现 LLM 成功率下降

**场景**：某天早上查看数据，发现成功率从 99% 降到 92%

**你的操作**：
1. **查看数据**：
   ```bash
   python scripts/view_metrics.py --date yesterday
   ```

2. **分析原因**：
   - 查看错误日志：`logs/error.log`
   - 检查是否是 API 服务商问题
   - 检查是否是网络问题

3. **同步团队**：
   - 在群里@开发负责人
   - 说明问题和影响

4. **跟踪解决**：
   - 开发排查问题
   - 修复后验证数据
   - 记录问题到知识库

### 示例 2：RAG 命中率持续走低

**场景**：周报复盘时发现 RAG 命中率从 97% 降到 88%

**你的操作**：
1. **数据对比**：
   ```bash
   python scripts/view_metrics.py --trend 30
   ```

2. **用户问题分析**：
   - 查看检索失败的 query
   - 分类整理缺失的知识点
   - 优先级排序

3. **内容运营**：
   - 安排补充知识库文档
   - 优先补充高频问题
   - 验证补充后的效果

4. **效果追踪**：
   - 每日查看命中率变化
   - 确认是否回升到目标值

### 示例 3：意图分布变化

**场景**：发现"无法回答"的意图占比从 5% 升到 15%

**你的操作**：
1. **查看分布**：
   ```bash
   python scripts/view_metrics.py
   ```

2. **抽样分析**：
   - 抽取 50 个"无法回答"的案例
   - 分析是否真的无法回答
   - 还是识别错误

3. **优化策略**：
   - 如果是识别错误 → 优化分类器
   - 如果是知识库缺失 → 补充内容
   - 如果是敏感问题 → 调整话术
